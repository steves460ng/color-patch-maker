# Color Patch Maker 작업 인수인계

기준: 2026-11-09, `main` 커밋 `4b9547f`(PR #28 병합 직후). 열린 PR 없음.

## 목표와 범위

- 사용자가 정한 규칙(두 채널 격자, 시작·끝 보간)으로 CMYK 패치를 만들어 인쇄용 PDF로 출력하는 Windows 데스크톱 도구(GUI)와 CLI. 작업자는 인쇄물을 실물 견본과 비교해 가장 가까운 CMYK 값을 고른다.
- 기준 문서는 `docs/DESIGN.md` 하나다. 진행 상태와 검증 결과는 `docs/PROGRESS.md`에서만 관리한다.
- 설계 단계 2-1~2-7은 모두 구현됐다. 남은 것: 다국어 배포본 교체와 Windows 영어 화면 확인, 4단계 현장 사이클, 리뷰에서 나온 다듬기.

## 작업 방식과 제약

- 역할 분담: 구현은 코딩 에이전트(Codex)가 지시문을 받아 PR로 올린다. 설계·문서·리뷰·병합 판단은 기획 담당(Claude)이 맡는다. 기획 담당은 명시적 지시가 없으면 코드를 쓰거나 고치지 않는다. 사용자는 방향 결정, Windows 빌드·실행 확인, 인쇄 현장 확인, 배포를 맡는다.
- 저장소 규칙은 `AGENTS.md`를 따른다. 핵심: DESIGN.md 2장에 있는 기능만 만든다, `main`에 직접 푸시하지 않는다, 강제 푸시하지 않는다, 끝낸 작업은 PROGRESS.md에 검사 결과와 함께 기록한다.
- 제품 규칙과 설계는 바꿀 수 있다. 바꿀 때는 DESIGN.md를 먼저 고치고(문서 PR) 그다음 구현 지시문을 쓴다. 큰 기능은 구조 정리(화면 변화 없음)와 기능 추가로 나눈다(예: 2-6 → 2-7).
- 문서 변경도 브랜치 → PR → squash 병합으로 처리한다. 병합된 head 브랜치는 자동 삭제된다.
- 코덱스 PR은 저장소 소유자 계정으로 올라와서 GitHub이 "Request changes" 리뷰를 막는다. 수정 요청은 일반 리뷰 댓글(줄 댓글 포함)로 남긴다.
- 사용자 지시 용어: "검토해"는 보고만, "병합해"·"문제없으면 병합해"는 확인 후 병합까지.
- 코덱스 지시문은 코드 블록 하나로 준다. 브랜치 이름, 먼저 읽을 문서, 범위, 테스트, 작업 규칙, PR 설명에 적을 것을 넣는다.
- 테스트는 Linux에서만 자동으로 돈다. Windows 전용 문제(경로 구분자, 인코딩, 개행)는 사용자가 `build_windows.ps1`을 돌릴 때 드러난다(PR #9, #28). 리뷰할 때 이 부분을 따로 본다. CI(Windows 자동 테스트)는 지금 쓰지 않는다.
- `README.md`(영문)와 `README.ko.md`(한글)는 앱 사용자용 소개 페이지이며 함께 고친다. 개발 내용은 `docs/DEVELOPMENT.md`에 둔다.
- 설계 문서에는 만들 기능만 적는다. 만들지 않을 기능의 이름이나 "제외" 목록을 쓰지 않는다(에이전트가 그 단어를 따라 만드는 일을 막기 위함).
- 이 파일은 내부 인수인계용이다. README나 다른 문서에서 링크하지 않는다.

## 확정된 결정 (DESIGN.md 7장 D-01~D-13 요약)

- CMYK 값은 0~100 정수만 쓴다. 소수 입력은 반올림하지 않고 오류. 이유: 인쇄기가 정수값만 출력.
- 한 PDF는 정확히 한 페이지. 넘치면 단일 페이지 PDF 여러 개(`_01`, `_02`). 이유: RIP가 페이지를 인식하지 못함. 기존 파일은 덮어쓰지 않고 `_v2`.
- 격자: 범위를 넘으면 0/100으로 고정하고 경고하며, 같은 값 패치도 그대로 출력. 짝수 배열의 기준색은 가운데 좌측·상단.
- 보간: 패치 수 기준, 시작·끝 포함, 정수 반올림(0.5 올림), 중복 허용.
- GUI와 CLI는 같은 엔진을 쓴다. 미리보기와 PDF는 엔진 `layout()`의 같은 데이터를 쓴다. 엔진은 Qt에 의존하지 않는다.
- GUI: PC 가로 2단 구성. 왼쪽 보조 패널(고정 방식 탭, 스크롤 본문, 고정 하단), 오른쪽 미리보기. Enter 키로 PDF를 만들지 않는다.
- 레이아웃 템플릿: 기본 제공 `default`(305×505, 여백 20, 간격 3, 자동)와 `card`(85.6×54, 여백 2, 간격 1, 패치 18mm, 한 장 4×2=8개). 사용자 템플릿 저장·불러오기·삭제. "기본값으로 되돌리기"는 레이아웃만 되돌림.
- 인쇄물에 헤더 없음. 라벨은 CMYK 값만(예: `C40 M70 Y20 K0`), 기준색 ` *`, 보간 시작 ` >`·끝 ` <`. 패치 ID는 매니페스트와 GUI에만 남김. 라벨 글자 4.5~7pt(최소 4.5pt는 인쇄로 확인해 확정).
- 화면 언어: GUI는 한국어·영어. 기본은 로케일, 언어 설정(자동·한국어·English)이 우선하고 다음 실행부터 적용. CLI 메시지는 영어만. 템플릿 표시 이름은 기본·카드 / Default·Card, 내부 식별자는 `default`·`card`. 문구는 `engine/messages.py` 사전에서만 만든다.
- 실행 파일 두 개(`cpm.exe` 콘솔, `ColorPatchMaker.exe` 창), 폴더째 배포(onedir). 앱 아이콘 `color_patch_maker/gui/resources/app.ico`.

## 제안과 가정 (확정 아님)

- 작업실 PC는 Windows로 가정(미확인).
- 카드 출력에서 패치가 왼쪽 위로 붙어 오른쪽 약 7mm, 아래 약 5mm가 비는 배치를 가운데 정렬로 바꿀지 검토 가능(설계 규칙 없음).
- 배포 ZIP은 `dist\ColorPatchMaker\*`와 `dist\cpm\cpm.exe`를 함께 묶는 방식으로 안내했다. `cpm.exe`가 GUI의 `_internal`로 실행되는지는 확인하지 않았다. 안 되면 `dist\cpm` 폴더를 따로 넣는다.

## 열린 질문과 막힌 점

- Windows 확인 남음:
  - 다국어 빌드로 배포본 교체, ZIP 안의 `cpm.exe --help` 실행.
  - 영어 화면: English 선택 후 재실행, 입력·레이아웃·폴더 유지, 템플릿 대화 상자 버튼, 1024×720 알림, 한국어로 되돌리기.
  - 언어 선택 상자가 높이 15px 고정이라 125%·150% 배율에서 글자가 잘리는지. 잘리면 다듬기 PR에서 고정 높이를 푼다.
- GUI 수동 확인 미완료(사용자가 더 써 보는 중): 폴더 선택 창, 폴더 열기, 템플릿 이름·덮어쓰기·삭제 대화 상자, 재실행 시 복원, Windows 글꼴에서 알림 영역 가림 여부.
- 현장 사이클(실물 견본 비교 → 패치 선택 → 선택값으로 재생성): 미실시.
- 리뷰에서 나온 미처리 다듬기:
  - 알림 영역 높이가 고정이라 세 줄 이상이면 잘린다.
  - PDF 완료 결과가 0/100 고정 경고를 덮어 가린다(입력을 바꾸면 다시 보임).
  - CLI `--template card --patch-size auto`가 거부된다(`auto`를 받지 못함).
  - CLI가 결과 JSON을 Windows 콘솔 인코딩(CP949)으로 출력해, CP949에 없는 문자가 경로에 있으면 실패할 수 있다.
  - GUI 배포 폴더가 큼(Linux 기준 약 230MB). 쓰지 않는 Qt 모듈을 뺄 여지가 있다.
  - PySide6가 기본 의존성이라 CLI만 설치해도 함께 설치된다.
  - 리뷰 중 로컬에서만 나왔던 영어 문구 후보(병합되지 않음): "Patch gap mm", "Open the output folder in File Explorer.", "label-only layout".
- 병합 후 남은 원격 브랜치(자동 삭제 설정 이전 것): `docs/gui-phase-split`, `feat/gui-layout`, `feat/gui-output`. 지워도 잃는 내용 없음. 이 작업 환경에서는 원격 브랜치 삭제 권한이 없었다.
- 버전 번호와 태그가 없다. 배포본이 어느 커밋인지는 PROGRESS.md 기록으로만 안다.
