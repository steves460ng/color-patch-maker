### 1단계 검증 범위와 한계

- 검사: `.venv/bin/python -m pytest -q` — 리뷰 수정 후 323개 통과, 실패·건너뜀 없음.
- Linux 콘솔 빌드 성공. 빌드 결과로 두 방식 PDF·JSON 생성과 역검사를 확인했다.
- 최초 테스트 수집 중 문법 오류를 수정한 후 전체 테스트를 다시 실행했다.
- 직접 의존성은 ReportLab, pikepdf, pytest, PyInstaller이며 `requirements-dev.txt`는 전이 의존성도 고정한다. 전이 패키지는 이 도구들의 설치·실행에 필요하다.
- 자동 검증은 DeviceCMYK·좌표·용지·라벨·페이지 수, 파일 충돌과 실패 시 정리를 포함한다.
- 라벨은 제안값 최소 6pt로 제한한다. 무제한 축소를 막는 초기 하한이며, 실물 인쇄 가독성은 미확인이다. 하한 미달은 엔진에서 출력 전에 거부한다.
- GUI는 미구현이며 공유 레이아웃을 사용하는 GUI 테스트는 2단계에 수행한다.
- Windows 빌드·Python 없는 Windows PC 실행·실물 인쇄 확인은 수행하지 않았다.

### PR #1 리뷰 반영 — 2026-11-09

- 자동 크기는 계산한 행·열 전체를 한 장에 배치한다. 지정 크기의 칸 수 계산에는 1e-9mm 허용 오차를 적용했다.
- 라벨 최소 6pt를 엔진에서 검사하고 계산한 글자 크기를 PDF 출력에 전달한다. 최소값은 인쇄 검증 전의 제안이며, 기존 약 2~3.5pt 축소를 차단하기 위해 정했다.
- 보간 시작·끝은 `>`·`<`로 표시한다. 기본 PDF 글꼴에서 출력 가능한 기호로 영어 단어를 대체했다.
- JSON 읽기는 UTF-8을 명시하고 숫자가 아닌 mm 입력에는 항목명과 한글 해결 안내를 제공한다.
- Linux / Python 3.12.14: 전체 323개 테스트 통과. 격자 1~15열 × 1~15행과 보간 2~60개, 지정 크기의 정확한 맞춤, 최장 CMYK 라벨의 6pt 경계, 오류 시 파일 미생성을 포함한다.
- 격자 전 조합은 충분한 용지에서 PDF 한 장을 검증했다. 기본 용지에서는 읽기 가능한 경우 한 장, 15×15 등 6pt 미달은 오류로 거부한다. 자동 크기 요구와 라벨 하한을 함께 적용한 결과다.
- Linux 콘솔 실행 파일 재빌드 성공. 실행 파일로 9×9 격자·60개 보간의 단일 페이지 출력과 역검사, 10mm 패치 라벨 오류를 확인했다.
- `git diff --check` 통과. 1단계 완료 표시는 위 재검사 결과를 기준으로 유지한다. Windows·실물 인쇄·GUI는 아직 미검증이다.
